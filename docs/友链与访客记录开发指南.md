## 1. Java → Go 概念对照表（贴在脑门上）

| Java / Spring | Go / Gin（本项目） | 备注 |
|---|---|---|
| `@Controller` 类 | `handler` 包里的 `XxxHandler` 结构体 | 方法挂在 struct 上，相当于 Bean 的方法 |
| `@Service` | `service` 包里的 `XxxService` 结构体 | 业务逻辑、参数校验都在这 |
| Mapper / `JpaRepository` | `repository` 包里的 `XxxRepo` 结构体 + GORM | GORM ≈ 一个"链式调用的 MyBatis-Plus" |
| `@Autowired` / IoC 容器 | **没有容器**，`cmd/server/main.go` 手动 `New` 并注入 | 依赖关系一眼可见，反而更直观 |
| `@GetMapping("/x")` | `router.go` 里 `v1.GET("/x", h.X.List)` | 路由集中在 `router.Setup`，像把所有注解收进一个文件 |
| Filter / Interceptor | Gin **中间件** `middleware.Xxx` | `r.Use(...)` 或分组 `.Use(...)` 挂载 |
| `@RequestBody XxxDTO` + `@Valid` | `c.ShouldBindJSON(&req)` + `binding:"required"` tag | 校验规则写在 struct tag 里 |
| Jackson 的 `@JsonProperty` | `json:"snake_case"` tag | 前后端字段映射 |
| `try/catch` + 全局 `@ExceptionHandler` | **没有异常**，函数返回 `error`；`response.Error()` 是你的全局兜底 | 这是最大的思维转变，见 §6 |
| `Objects.equals` / null 判断 | `nil` 判断 + `errors.Is(err, gorm.ErrRecordNotFound)` | "查不到"在 repo 层翻译成 `(nil, nil)` 返回 |
| Lombok `@Data` | 没有，字段+tag 一个个写 | 幸好 DTO 都很短 |

一句话总览本项目请求链路（和 Java 完全同构）：

```text
HTTP 请求 → router.go（路由+权限分组）→ handler（解析参数/封响应）
        → service（业务校验）→ repository（SQL）→ GORM → MySQL
```

## 2. 整体设计

### 2.1 友链（FriendLink）

**表设计**（复用已有的 `model.FriendLink`，GORM 自动建表 `friend_links`）：

| 字段 | 类型 | 说明 |
|---|---|---|
| id | bigint PK | |
| name | varchar(100) | 站点名称，必填 |
| avatar | varchar(500) | 头像 URL，可空（前端给默认头像） |
| url | varchar(500) | 站点地址，必填 |
| description | varchar(500) | 一句话介绍 |
| status | tinyint | 1=上架 0=下架（对应"上下线"按钮） |
| sort | int | 越小越靠前，同权重新的在前 |
| created_at / updated_at | datetime | GORM 自动维护 |

**API 设计**（遵守 `docs/api-v1.md` 的通用约定，响应统一 `{code, message, data}`）：

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| GET | `/api/v1/friend-links` | 公开 | 只返回 `status=1`，`sort ASC, id DESC`；友链数量少，**不分页**，直接返回数组 |
| POST | `/api/v1/admin/friend-links` | JWT | 新增，status 默认 1 |
| PUT | `/api/v1/admin/friend-links/:id` | JWT | 全量更新 |
| PUT | `/api/v1/admin/friend-links/:id/status` | JWT | 上下线切换：`{"status": 0}` |
| DELETE | `/api/v1/admin/friend-links/:id` | JWT | 硬删除（友链没有软删除价值，删了就删了） |

### 2.2 访客记录（"谁访问过"）

博客**没有注册用户**（只有一个管理员），所以"谁"需要一个身份方案。设计如下：

**访客身份 `visitor_key`，两级识别：**

1. **前端生成 UUID 存 localStorage**，每次请求带自定义请求头 `X-Visitor-ID` → 同一个浏览器 = 同一个访客（清缓存才变）
2. 后端发现没带头 → 降级用 `sha256(IP + User-Agent)` → 同一网络同一设备也算同一访客

**昵称 `nickname`（可选）**：前端如果让访客填过昵称（比如留言时用的名字），带 `X-Visitor-Name` 头，一并入库。这样后台看到的是"张三 来过 8 次，最近一次 9月26日"，而不是一串哈希。

**表设计 `visit_logs`**（每次访问一条，明细表）：

| 字段 | 类型 | 说明 |
|---|---|---|
| id | bigint PK | |
| visitor_key | varchar(64), index | 访客标识（UUID 或 IP+UA 哈希） |
| nickname | varchar(64) | 可空 |
| path | varchar(255) | 访问的接口路径，如 `/api/v1/articles` |
| ip | varchar(64) | |
| user_agent | varchar(512) | 浏览器标识，可判断设备类型 |
| referer | varchar(512) | 从哪跳来的 |
| created_at | datetime, index | 访问时间 |

> 不单独建"访客汇总表"：个人博客流量下，用 SQL 聚合（`GROUP BY visitor_key`）就够了，等以后量大了再考虑。

**记录方式：Gin 中间件自动记录**（对应 Spring 的 Interceptor），规则：

- 挂在 `/api/v1` 公共分组上，**自动**记录每一次前台请求，前端零改动（昵称头除外）
- 跳过 `/admin/*`（自己后台操作不算访客）和 `/healthz`（部署探活）
- **异步落库**：中间件里起 goroutine 写 MySQL，不阻塞响应（对应 Java 里丢线程池，这里是 `go func(){}`，见 §6 的坑）

**API 设计**（全部 JWT，只有站长看得到）：

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/v1/admin/visits` | 访问明细列表，分页，`keyword` 可按昵称/路径模糊搜索 |
| GET | `/api/v1/admin/visits/summary` | 汇总：总访问数、今日访问、独立访客数、今日独立访客、最常访问的接口 TOP5、最近访客列表（按 visitor_key 聚合） |

前端展示建议：后台管理页加一个"访客"标签页，用 summary 接口画几张数字卡片 + 一个最近访客表格。

### Step 2 — repository（新建 `internal/repository/friend_link.go`）

```go
package repository

import (
	"errors"

	"abingblog-backend/internal/model"

	"gorm.io/gorm"
)

// FriendLinkRepo 友链数据访问层：只负责 SQL，不含业务逻辑
type FriendLinkRepo struct {
	db *gorm.DB
}

func NewFriendLinkRepo(db *gorm.DB) *FriendLinkRepo { return &FriendLinkRepo{db: db} }

// List 查友链列表。statusOnlyPublished=true 时只查上架的（公共接口用）
func (r *FriendLinkRepo) List(onlyPublished bool) ([]model.FriendLink, error) {
	query := r.db.Model(&model.FriendLink{})
	if onlyPublished {
		query = query.Where("status = ?", 1)
	}
	list := make([]model.FriendLink, 0) // 注意：make 初始化，见 §6 第 5 条
	err := query.Order("sort ASC, id DESC").Find(&list).Error
	return list, err
}

// GetByID 按 ID 查友链；查不到返回 (nil, nil)，由 service 翻译成业务错误
func (r *FriendLinkRepo) GetByID(id uint) (*model.FriendLink, error) {
	var f model.FriendLink
	err := r.db.First(&f, id).Error
	if errors.Is(err, gorm.ErrRecordNotFound) {
		return nil, nil
	}
	return &f, err
}

func (r *FriendLinkRepo) Create(f *model.FriendLink) error {
	return r.db.Create(f).Error
}

// Update 全量更新业务字段（用 map 保证空值也能覆盖进数据库）
func (r *FriendLinkRepo) Update(f *model.FriendLink) error {
	return r.db.Model(f).Updates(map[string]any{
		"name":        f.Name,
		"avatar":      f.Avatar,
		"url":         f.URL,
		"description": f.Description,
		"sort":        f.Sort,
		"status":      f.Status,
	}).Error
}

// UpdateStatus 只改上下线状态
func (r *FriendLinkRepo) UpdateStatus(id uint, status int) error {
	return r.db.Model(&model.FriendLink{}).Where("id = ?", id).
		Update("status", status).Error
}

// Delete 删除友链（物理删除）
func (r *FriendLinkRepo) Delete(id uint) error {
	return r.db.Delete(&model.FriendLink{}, id).Error
}
```

### Step 3 — service（填充 `internal/service/FriendLink.go`，现在是空的）

```go
package service

import (
	"strings"

	"abingblog-backend/internal/errcode"
	"abingblog-backend/internal/model"
	"abingblog-backend/internal/repository"
)

// FriendLinkService 友链业务逻辑层：参数校验、状态规则
type FriendLinkService struct {
	repo *repository.FriendLinkRepo
}

func NewFriendLinkService(repo *repository.FriendLinkRepo) *FriendLinkService {
	return &FriendLinkService{repo: repo}
}

// FriendLinkReq 创建/更新友链的请求体（前后端契约的一部分）
type FriendLinkReq struct {
	Name        string `json:"name"`
	Avatar      string `json:"avatar"`
	URL         string `json:"url"`
	Description string `json:"description"`
	Sort        int    `json:"sort"`
	Status      int    `json:"status"` // 1 上架 / 0 下架，缺省 1
}

func (s *FriendLinkService) validate(req *FriendLinkReq) error {
	if strings.TrimSpace(req.Name) == "" {
		return errcode.New(errcode.CodeFriendNameEmpty, "友链名称不能为空")
	}
	if strings.TrimSpace(req.URL) == "" {
		return errcode.New(errcode.CodeFriendURLEmpty, "友链地址不能为空")
	}
	if req.Status != 0 && req.Status != 1 {
		return errcode.New(errcode.CodeBadFriendStatus, "状态只能为 0（下架）或 1（上架）")
	}
	return nil
}

// ListPublic 公共列表：只返回上架友链
func (s *FriendLinkService) ListPublic() ([]model.FriendLink, error) {
	return s.repo.List(true)
}

// AdminList 后台列表：含下架友链
func (s *FriendLinkService) AdminList() ([]model.FriendLink, error) {
	return s.repo.List(false)
}

// Create 新增友链：状态缺省上架
func (s *FriendLinkService) Create(req FriendLinkReq) (*model.FriendLink, error) {
	if strings.TrimSpace(req.Name) == "" {
		return nil, errcode.New(errcode.CodeFriendNameEmpty, "友链名称不能为空")
	}
	if strings.TrimSpace(req.URL) == "" {
		return nil, errcode.New(errcode.CodeFriendURLEmpty, "友链地址不能为空")
	}
	f := &model.FriendLink{
		Name:        strings.TrimSpace(req.Name),
		Avatar:      req.Avatar,
		URL:         strings.TrimSpace(req.URL),
		Description: req.Description,
		Sort:        req.Sort,
		Status:      1, // 新增默认上架
	}
	if err := s.repo.Create(f); err != nil {
		return nil, err
	}
	return f, nil
}

// Update 全量更新
func (s *FriendLinkService) Update(id uint, req FriendLinkReq) (*model.FriendLink, error) {
	if err := s.validate(&req); err != nil {
		return nil, err
	}
	f, err := s.repo.GetByID(id)
	if err != nil {
		return nil, err
	}
	if f == nil {
		return nil, errcode.New(errcode.CodeFriendLinkNotFound, "友链不存在")
	}
	f.Name = strings.TrimSpace(req.Name)
	f.Avatar = req.Avatar
	f.URL = strings.TrimSpace(req.URL)
	f.Description = req.Description
	f.Sort = req.Sort
	f.Status = req.Status
	if err := s.repo.Update(f); err != nil {
		return nil, err
	}
	return f, nil
}

// UpdateStatus 上下线切换
func (s *FriendLinkService) UpdateStatus(id uint, status int) (*model.FriendLink, error) {
	if status != 0 && status != 1 {
		return nil, errcode.New(errcode.CodeBadFriendStatus, "状态只能为 0（下架）或 1（上架）")
	}
	f, err := s.repo.GetByID(id)
	if err != nil {
		return nil, err
	}
	if f == nil {
		return nil, errcode.New(errcode.CodeFriendLinkNotFound, "友链不存在")
	}
	if err := s.repo.UpdateStatus(id, status); err != nil {
		return nil, err
	}
	f.Status = status
	return f, nil
}

// Delete 删除友链
func (s *FriendLinkService) Delete(id uint) error {
	f, err := s.repo.GetByID(id)
	if err != nil {
		return err
	}
	if f == nil {
		return errcode.New(errcode.CodeFriendLinkNotFound, "友链不存在")
	}
	return s.repo.Delete(id)
}
```

> 注意 `Create` 里没有复用 `validate()`：因为 Go 的 int 零值就是 0，**无法区分"没传 status"和"传了 0（下架）"**。这是 Java（`Integer` 可为 null）和 Go 的一个经典差异，所以新增接口直接约定"新增默认上架"。如果觉得别扭，把 Status 改成 `*int`（指针≈可空 Integer）也行，但对友链这点场景不值得。

### Step 5 — handler（填充 `internal/handler/FriendLink.go`）

```go
package handler

import (
	"net/http"

	"abingblog-backend/internal/errcode"
	"abingblog-backend/internal/response"
	"abingblog-backend/internal/service"

	"github.com/gin-gonic/gin"
)

// FriendLinkHandler 友链接口层：解析请求 → 调 service → 封装响应
type FriendLinkHandler struct {
	svc *service.FriendLinkService
}

func NewFriendLinkHandler(svc *service.FriendLinkService) *FriendLinkHandler {
	return &FriendLinkHandler{svc: svc}
}

// ListPublic 公共友链列表：只返回上架友链，不分页
func (h *FriendLinkHandler) ListPublic(c *gin.Context) {
	list, err := h.svc.ListPublic()
	if err != nil {
		response.Error(c, err)
		return
	}
	dtos := make([]friendLinkDTO, 0, len(list))
	for i := range list {
		dtos = append(dtos, toFriendLinkDTO(&list[i]))
	}
	response.OK(c, gin.H{"list": dtos, "total": len(dtos)})
}

// AdminList 后台友链列表：含下架
func (h *FriendLinkHandler) AdminList(c *gin.Context) {
	list, err := h.svc.AdminList()
	if err != nil {
		response.Error(c, err)
		return
	}
	dtos := make([]friendLinkDTO, 0, len(list))
	for i := range list {
		dtos = append(dtos, toFriendLinkDTO(&list[i]))
	}
	response.OK(c, gin.H{"list": dtos, "total": len(dtos)})
}

// Create 新增友链（后台）
func (h *FriendLinkHandler) Create(c *gin.Context) {
	var req service.FriendLinkReq
	if err := c.ShouldBindJSON(&req); err != nil {
		response.Fail(c, http.StatusBadRequest, errcode.CodeBadParam, "请求参数错误: "+err.Error())
		return
	}
	f, err := h.svc.Create(req)
	if err != nil {
		response.Error(c, err)
		return
	}
	response.OK(c, toFriendLinkDTO(f))
}

// Update 全量更新友链（后台）
func (h *FriendLinkHandler) Update(c *gin.Context) {
	id := pathParamUint(c)
	if id == 0 {
		response.Fail(c, http.StatusBadRequest, errcode.CodeBadParam, "无效的友链 ID")
		return
	}
	var req service.FriendLinkReq
	if err := c.ShouldBindJSON(&req); err != nil {
		response.Fail(c, http.StatusBadRequest, errcode.CodeBadParam, "请求参数错误: "+err.Error())
		return
	}
	f, err := h.svc.Update(id, req)
	if err != nil {
		response.Error(c, err)
		return
	}
	response.OK(c, toFriendLinkDTO(f))
}

// UpdateStatus 上下线（后台）
func (h *FriendLinkHandler) UpdateStatus(c *gin.Context) {
	id := pathParamUint(c)
	if id == 0 {
		response.Fail(c, http.StatusBadRequest, errcode.CodeBadParam, "无效的友链 ID")
		return
	}
	var req struct {
		Status int `json:"status"`
	}
	if err := c.ShouldBindJSON(&req); err != nil {
		response.Fail(c, http.StatusBadRequest, errcode.CodeBadParam, "请求参数错误: "+err.Error())
		return
	}
	f, err := h.svc.UpdateStatus(id, req.Status)
	if err != nil {
		response.Error(c, err)
		return
	}
	response.OK(c, toFriendLinkDTO(f))
}

// Delete 删除友链（后台）
func (h *FriendLinkHandler) Delete(c *gin.Context) {
	id := pathParamUint(c)
	if id == 0 {
		response.Fail(c, http.StatusBadRequest, errcode.CodeBadParam, "无效的友链 ID")
		return
	}
	if err := h.svc.Delete(id); err != nil {
		response.Error(c, err)
		return
	}
	response.OK(c, nil)
}
```

> `UpdateStatus` 里那个匿名 struct 是 Go 特色：只在一处用的小结构体可以现场定义，省得到处建类。

```go
package repository

import (
	"time"

	"abingblog-backend/internal/model"

	"gorm.io/gorm"

// VisitLogRepo 访问记录数据访问层
type VisitLogRepo struct {
	db *gorm.DB
}

func NewVisitLogRepo(db *gorm.DB) *VisitLogRepo { return &VisitLogRepo{db: db} }

// Create 写入一条访问记录（由中间件异步调用）
func (r *VisitLogRepo) Create(l *model.VisitLog) error {
	return r.db.Create(l).Error
}

// VisitQuery 明细列表查询条件
type VisitQuery struct {
	Page     int
	PageSize int
	Keyword  string // 模糊匹配昵称或路径
}

// List 分页查访问明细，按时间倒序
func (r *VisitLogRepo) List(q VisitQuery) ([]model.VisitLog, int64, error) {
	query := r.db.Model(&model.VisitLog{})
	if q.Keyword != "" {
		kw := "%" + q.Keyword + "%"
		query = query.Where("nickname LIKE ? OR path LIKE ?", kw, kw)
	}
	var total int64
	if err := query.Session(&gorm.Session{}).Count(&total).Error; err != nil {
		return nil, 0, err
	}
	list := make([]model.VisitLog, 0)
	err := query.Session(&gorm.Session{}).
		Order("created_at DESC, id DESC").
		Offset((q.Page - 1) * q.PageSize).Limit(q.PageSize).
		Find(&list).Error
	return list, total, err
}

// VisitorSummary 按访客聚合的一行（最近访客列表用）
type VisitorSummary struct {
	VisitorKey string    `json:"visitor_key"`
	Nickname   string    `json:"nickname"`
	Visits     int64     `json:"visits"`
	LastSeenAt time.Time `json:"last_seen_at"`
}

// SummarizeByVisitor 按访客聚合：每个 visitor_key 的访问次数、最近一次时间
func (r *VisitLogRepo) SummarizeByVisitor(limit int) ([]VisitorSummary, error) {
	out := make([]VisitorSummary, 0)
	err := r.db.Model(&model.VisitLog{}).
		Select("visitor_key, MAX(nickname) AS nickname, COUNT(*) AS visits, MAX(created_at) AS last_seen_at").
		Group("visitor_key").
		Order("last_seen_at DESC").
		Limit(limit).
		Find(&out).Error
	return out, err
}

// TopPath 最常访问的接口
type TopPath struct {
	Path   string `json:"path"`
	Visits int64  `json:"visits"`
}

// TopPaths 访问次数 TOP N 接口
func (r *VisitLogRepo) TopPaths(limit int) ([]TopPath, error) {
	out := make([]TopPath, 0)
	err := r.db.Model(&model.VisitLog{}).
		Select("path, COUNT(*) AS visits").
		Group("path").
		Order("visits DESC").
		Limit(limit).
		Find(&out).Error
	return out, err
}

// VisitStats 汇总数字
type VisitStats struct {
	Total          int64 `json:"total"`           // 累计访问次数
	Today          int64 `json:"today"`           // 今日访问次数
	DistinctUsers  int64 `json:"distinct_users"`  // 累计独立访客
	TodayDistinct  int64 `json:"today_distinct"`  // 今日独立访客
}

// Stats 汇总统计
func (r *VisitLogRepo) Stats() (VisitStats, error) {
	var s VisitStats
	today0 := time.Now().Format("2006-01-02") // Go 的日期格式就是这么写，别写成 yyyy-MM-dd！
	err := r.db.Model(&model.VisitLog{}).Select(
		"COUNT(*) AS total, COUNT(DISTINCT visitor_key) AS distinct_users",
	).Scan(&s).Error
	if err != nil {
		return s, err
	}
	err = r.db.Model(&model.VisitLog{}).
		Where("created_at >= ?", today0).
		Select("COUNT(*) AS today, COUNT(DISTINCT visitor_key) AS today_distinct").
		Scan(&s).Error
	return s, err
}
```

> 两个 Java 里没有的写法注意：
> ① `Select("... AS nickname, COUNT(*) AS visits")` + `Scan(&out)` ≈ MyBatis 里写一段自定义 SQL 映射到 ResultMap，GORM 按字段名对齐 struct。
> ② Go 格式化日期没有 `yyyy-MM-dd`，要用 `2006-01-02`（Go 的诞生时间做占位符，官方梗，背下来）。

### Step 3 — 中间件（新建 `internal/middleware/visit.go`）

这是本功能的核心，对应 Spring 的 HandlerInterceptor：

```go
package middleware

import (
	"crypto/sha256"
	"encoding/hex"
	"log"
	"strings"

	"abingblog-backend/internal/model"
	"abingblog-backend/internal/repository"

	"github.com/gin-gonic/gin"
)

// VisitTracker 访问记录中间件：记录每次前台请求"是谁、何时、访问了什么"。
// 访客身份两级识别：
//  1. 前端 localStorage 生成的 UUID，通过 X-Visitor-ID 请求头带上（首选）
//  2. 没带头的，降级用 sha256(IP + User-Agent)
//
// 异步落库：go func 里写 MySQL，不阻塞响应。博客流量下安全；
// 量大了换 buffered channel + 单 worker（对应 Java 的线程池 + 队列）。
func VisitTracker(repo *repository.VisitLogRepo) gin.HandlerFunc {
	return func(c *gin.Context) {
		ua := c.Request.UserAgent()
		ip := c.ClientIP()

		// 1. 确定访客身份
		key := strings.TrimSpace(c.GetHeader("X-Visitor-ID"))
		if len(key) > 64 {
			key = key[:64] // 防恶意超长头
		}
		if key == "" {
			sum := sha256.Sum256([]byte(ip + "|" + ua))
			key = hex.EncodeToString(sum[:])[:64]
		}
		nickname := strings.TrimSpace(c.GetHeader("X-Visitor-Name"))
		if len(nickname) > 64 {
			nickname = nickname[:64]
		}

		// 2. 先取出需要的数据再起 goroutine！
		//    gin.Context 在请求结束后会被回收复用，异步代码里绝不能再碰 c，
		//    否则就是 Java 里"在异步线程里用已归还的 HttpServletRequest"同款事故。
		entry := model.VisitLog{
			VisitorKey: key,
			Nickname:   nickname,
			Path:       c.Request.URL.Path,
			IP:         ip,
			UserAgent:  truncate(ua, 512),
			Referer:    truncate(c.Request.Header.Get("Referer"), 512),
		}

		// 3. 异步写库，不阻塞响应
		go func() {
			defer func() {
				if r := recover(); r != nil { // goroutine 里的 panic 不会自动冒泡，必须自己兜住
					log.Printf("记录访问日志失败(panic): %v", r)
				}
			}()
			if err := repo.Create(&entry); err != nil {
				log.Printf("记录访问日志失败: %v", err)
			}
		}()

		// 4. 放行，继续后面的处理（不调 Next 就等于拦截了请求！）
		c.Next()
	}
}

func truncate(s string, n int) string {
	if len(s) <= n {
		return s
	}
	return s[:n]
}
```

```js
function getVisitorId() {
  let id = localStorage.getItem('visitor_id')
  if (!id) {
    id = crypto.randomUUID()
    localStorage.setItem('visitor_id', id)
  }
  return id
}

// 每次请求自动带上
axios.interceptors.request.use((config) => {
  config.headers['X-Visitor-ID'] = getVisitorId()

  if (name) config.headers['X-Visitor-Name'] = name
  return config
})
```

## 6. Java 开发者写 Go 最容易踩的 6 个坑（本次功能全覆盖）

1. **没有异常，只有 error 返回值。** 每个 `err != nil` 都要处理，编译器不强制，但漏一处就是裸奔。本项目套路固定：service 层 `errcode.New(...)`，handler 层 `response.Error(c, err)` 兜底，几乎不用动脑。
2. **没有 `private` 关键字，大小写即可见性。** `friendLinkDTO` 小写 = 包内私有（≈同类内使用），`FriendLinkService` 大写 = 公开。函数名大写开头（如 `ListPublic`）≈ public 方法。
3. **没有继承。** 想复用就"组合"：struct 里嵌 `*repository.FriendLinkRepo` 字段。本项目所有 Service/Handler 都是组合出来的。
4. **未初始化的 slice 是 nil，JSON 会变 `null` 而不是 `[]`。** 所以列表统一 `make([]T, 0)` 开头（`List` 里都是这么写的）。
5. **goroutine 里不能碰 `gin.Context`。** 请求结束后 Context 会被复用，必须先把 `IP/UA/Path` 拷到局部变量再 `go func()`——就像在异步线程里持有已回收的 HttpServletRequest 会出鬼一样。`VisitTracker` 中间件已示范正确姿势。
6. **`:=` 和 `=` 不一样。** `:=` 是"声明并赋值"（新变量），`=` 是纯赋值。同作用域里 `x := 1` 之后又 `x := 2` 直接编译报错，别硬扛编译器。

## 10. 友链实现版：访客自助提交 + 管理端审核（2026-09-28 第三版）

需求升级：**访客可以创建/修改/删除"自己的"友链，但要经管理端审核才会上架展示**。已全部落地并通过 `go build` / `go vet`，本节记录最终设计与关键决策，供复盘学习。

### 10.1 归属方案：不引入注册，复用访客 UUID

博客没有注册用户，"自己的"靠 `X-Visitor-ID`（前端 visitor.ts 自动附带）认领：

- `friend_links` 表新增 `owner_id varchar(64)`（索引），存提交者的访客 UUID
- 访客的增删改接口**不需要 JWT**——UUID 本身就是归属凭证；清了 localStorage 就等于换了个身份（丢了也只是一条友链，可接受）
- 恶意场景天然受限：改别人 UUID 顶多伪造归属去删别人的友链申请，管理员审核环节兜底

### 10.2 状态机：0 待审核 → 1 上架 / 2 驳回

```go
FriendLinkPending  = 0 // 提交后的初始状态
FriendLinkApproved = 1 // 前台可见
FriendLinkRejected = 2 // 管理员否决
```

**关键规则：访客修改自己的友链后，状态强制打回 0**——否则先提交正常内容过审，再改成垃圾内容就绕过审核了。这是所有 UGC 审核流的通用套路（对应 Java 里的"编辑后重审"）。

### 10.3 路由终稿

| 方法 | 路径 | 鉴权 | 说明 |
|---|---|---|---|
| GET | `/api/v1/friend-links` | 无 | 前台列表，只出 status=1 |
| GET | `/api/v1/friend-links/mine` | X-Visitor-ID | 我的提交（含待审核/已驳回） |
| POST | `/api/v1/friend-links/mine` | X-Visitor-ID | 提交友链，强制 status=0 |
| PUT | `/api/v1/friend-links/mine/:id` | X-Visitor-ID | 改自己的，改完打回 0 |
| DELETE | `/api/v1/friend-links/mine/:id` | X-Visitor-ID | 删自己的（软删除） |
| GET | `/api/v1/admin/friend-links?status=` | JWT | 后台列表，缺省查全部 |
| PUT | `/api/v1/admin/friend-links/:id` | JWT | 编辑 + 审核（body 带 status） |
| DELETE | `/api/v1/admin/friend-links/:id` | JWT | 删除任意友链 |

用 `/mine` 子路径而不是让访客直接打 `PUT /friend-links/:id`，是为了和公共只读 GET 在路由层面就分清"这是访客自助操作"，归属校验放在 service 层兜底（`f.OwnerID != visitorID` → `CodeFriendNotOwner`）。

### 10.4 curl 自测脚本

```bash
# 1. 提交友链（模拟访客 A）
curl -X POST http://localhost:8080/api/v1/friend-links/mine \
  -H "Content-Type: application/json" -H "X-Visitor-ID: visitor-A" \
  -d '{"name":"阿冰的小站","url":"https://example.com","description":"hello"}'

# 2. A 查自己的（应看到 status=0 待审核）
curl http://localhost:8080/api/v1/friend-links/mine -H "X-Visitor-ID: visitor-A"

# 3. 前台列表（此时应为空）
curl http://localhost:8080/api/v1/friend-links

# 4. 管理员登录后审核通过（status: 1）
curl -X PUT http://localhost:8080/api/v1/admin/friend-links/1 \
  -H "Authorization: Bearer <token>" -H "Content-Type: application/json" \
  -d '{"name":"阿冰的小站","url":"https://example.com","description":"hello","status":1,"sort":0}'

# 5. 前台列表应出现；访客 B 试图删 A 的友链 → 应报 5103 只能操作自己提交的友链
curl -X DELETE http://localhost:8080/api/v1/friend-links/mine/1 -H "X-Visitor-ID: visitor-B"
```
